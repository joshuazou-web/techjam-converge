## Project details → About the project

```markdown
## Inspiration

The starter agent for this track scores **0.107**. It is not badly written — it is asking the
wrong question. Like most conversational search, it measures *similarity* between what the shopper
said and what the catalog contains.

But look at where a shopper's words come from. They are describing a product that already exists.
Their utterances are *generated by* the thing we are trying to find. Similarity throws that
structure away.

So Converge asks a sharper question:

> **If this product were the one they want, would they have said exactly what they just said?**

Products that fail that test are *impossible*, not merely unlikely.

## What it does

Converge is a multi-turn shopping agent over a frozen 50,000-product Amazon catalog. Each turn it
parses what the shopper said into exact constraints, replays the whole conversation against every
candidate product, and keeps only the ones that could have produced it. That survivor set is an
exact posterior — retrieval becomes set intersection rather than scoring.

Running the same user model **forwards** answers the question that decides how fast a shopping
conversation ends: *which question would tell me the most, before I spend a turn asking it?* For
every attribute the agent simulates the answer each surviving candidate would give, groups them by
that answer, and measures the entropy left behind. It asks the argmax, and stops asking the moment
no question can split the pool.

Then it does something most recommenders will not: **it shows one product instead of ten.** The
scoring function rewards rank (0.30 × MRR) far more than it punishes a turn (0.20 × efficiency
across ten turns), so converting at rank 1 next turn beats converting at rank 6 now. The agent
withholds the long tail while a question can still narrow the field, and always opens the full
slate by turn 4 so caution can never cost the conversion.

One more idea closed the gap to a perfect hit rate: **the conversation continuing is itself a
label.** The harness stops the instant the target appears on a scored slate, so every product
already shown is provably *not* the target. Feed that back and every turn offers something new.
(With one exception that matters: an Intent Override session suppresses conversions until the
override lands, so nothing shown before it is refuted — the agent clears its refutation set when
the override arrives.)

**Result on the 200-session public set, produced by the unmodified official evaluator:**

| | Hit@10 | MRR | MTTC | TechnicalScore |
| --- | ---: | ---: | ---: | ---: |
| Official weak BM25 starter | 0.125 | 0.068 | 9.81 | **0.1067** |
| Converge | **1.000** | **0.9835** | **1.96** | **0.9760** |

200/200 sessions converted, 96% of them at rank 1, in a mean of 1.96 turns out of 10 — with **no
LLM, no network call, no third-party package, $0.00 per session and 7.7 ms per turn.**

## How we built it

Five stages per turn, each a small module:

- **Understand** — exact contract parsing, then a lexicon-recovery layer that finds catalog
  constraints quoted inside paraphrased text.
- **Condition** — transcript replay against candidates, over an inverted index of the 60,670
  distinct constraint strings in the catalog, with a four-rung relaxation ladder (drop the
  overridden slot, drop slot ordering, fall back to graded evidence) so one bad parse can never
  eliminate the right answer.
- **Orchestrate** — a per-turn plan (`commit` / `focus` / `explore` / `recover`) chosen from the
  retrieval mode, pool width, turns left, and whether an override is pending. The plan sets the
  route mix and the conversational move.
- **Rank** — three routes fused with weighted Reciprocal Rank Fusion: the structural posterior,
  SQLite FTS5 BM25 over full product text, and an in-memory character-3-gram cosine. Re-ranked with
  a purchase-volume prior and safe personalisation from the anonymised preference tags only.
- **Ask** — expected-information-gain question selection, with a 2% "naturalness margin" so a named
  attribute ("Any material you prefer?") beats an open-ended one when the gain is effectively tied.

Everything runs in process memory on the Python standard library. No vector database, no service,
no GPU, no credentials.

## Challenges we ran into

**Ambiguous separators.** The simulator joins two constraints with `"; "` — but a single constraint
can itself contain `"; "`. We resolve the segmentation against the catalog: a split whose parts are
both real constraints wins.

**Recall that made things worse.** A first paraphrase-recovery pass searched every span for the
longest catalog match. It recovered more quotes and *lost 0.10 TechnicalScore*, because a wrong
constraint does not merely fail to help — it eliminates the right answer. The shipped version scans
suffixes only, first match wins. Precision beats recall when your retrieval is a set intersection.

**Knowing when to stop being clever.** Sweeping the ranking weights moved the score between 0.903
and 0.912 — inside the noise band of a 200-session dev set. We stopped tuning, took a round number,
and spent the time on mechanisms that moved the score by 0.06–0.12 instead.

## Accomplishments that we're proud of

- **9.1× the official baseline** (0.9760 vs 0.1067), with a perfect hit rate.
- **An ablation, not a claim.** Every component is switchable and every arm is a full run of the
  official evaluator: inverse user model −0.123, information-gain questions −0.070, confidence-gated
  slates −0.060, popularity prior −0.023.
- **We measured our own weakest assumption instead of hiding it.** A robustness harness holds the
  customer *policy* byte-for-byte identical and rewrites only the wording: 0.9760 → 0.8904 (light
  paraphrase) → 0.7933 (heavy). Break every template and it still scores 7.4× the baseline.
- **A parity test over all 50,000 products** asserts our re-implementation of the constraint model
  matches the official evaluator, so a contract change fails loudly instead of quietly degrading.
- **Zero cost, zero dependencies, 7.7 ms per turn** — this ships to production on a laptop.

## What we learned

Specifying the user model explicitly is worth more than any amount of similarity tuning. Once you
can *simulate* the person you are talking to, retrieval, clarification, and slate size all stop
being heuristics and become arithmetic on the same object.

We also learned to read the objective function like a product spec. The decision to show one
product instead of ten came straight out of the scoring weights, and it was worth 0.06 on its own —
more than every ranking-weight sweep combined.

## What's next for Converge

1. **Learn the user model instead of specifying it.** The replay engine only needs a function from
   (product, question) → predicted answer. Fit that from real dialogue logs and the same posterior
   machinery works on open-world language; the templates become one special case.
2. **Value-of-information with a real cost model** — conversion value, abandonment risk, and
   cognitive load instead of a threshold derived from the metric weights.
3. **Scale past 50k.** Exact intersection is fine here; a 10⁷-product catalog needs sketching and a
   learned candidate generator in front of it.
4. **Explanations for free.** Every recommendation already carries a machine-readable reason —
   which constraints it satisfies, which competitors it eliminated. Surfacing that is a trust
   feature and roughly a day of work.
```
